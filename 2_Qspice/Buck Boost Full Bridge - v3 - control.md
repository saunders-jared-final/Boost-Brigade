# Buck Boost Full Bridge - v3 - control.qsch

One sheet: the hand-drawn `Buck Boost Full Bridge - v3.qsch` (untouched) with the firmware control stack integrated.
Generated by `Claude's outputs/integrate_control_v3.py` (rerun it after editing the generator; hand edits to the
sheet and the generator do not mix, so keep an edited copy under another name).

## Files that must sit next to the sheet

| file | what |
|---|---|
| `shuffler_ctrl_dll2.dll` | the control stack (6_RTOS/ctrl_core) as a QSPICE C-block, built from `ctrl_dll/` with the current `params.h` (gain set sps-params-2.20261015-1950-3mod-qspice200-bench, the 200 kHz M flashed on the Nucleo) |
| `ctrl_M2.txt` | the same M as plain text, used when `MSEL=2` (edit it to try another M without rebuilding the DLL) |
| `HalfBridge_Driver.qsch` | the hierarchical driver sheet the v3 drawing already uses |
| `MyLibrary.lib` | the `pvmi` module model, found through QSPICE's library path (OneDrive Documents/QSPICE) as for v3 |

## What changed against v3

- SW1 / SW2 (fixed 50 % pulses) are gone. Each half-bridge driver gets its own PWM pair from the control block:
  `PWM_AH1/PWM_AL1` = converter 1 leg A (M3/M4), `PWM_BH1/PWM_BL1` = leg B (M1/M2), `PWM_?H2/PWM_?L2` the same
  for converter 2 (M5/M6, M7/M8). The comparators are HRTIM-style: top FET on while RAMP < duty - Tdead/Tsw,
  bottom FET while duty < RAMP < 1 - Tdead/Tsw, leg B's ramp half a period later. All low at t = 0 so the
  operating point is the same as v3's.
- The sheet's own 0 V sources in the inductor windings (V4 = A1, V7 = B1, V5 = A2, V6 = B2, positive from the
  winding into the midpoint) feed TMCS1126 models: 1.65 V + 100 mV/A (A), 1.65 V - 25 mV/A (B, reversed as
  mounted), 500 kHz output pole.
- The INA239 nodes are the string buses: `Out` (PV1+), `PV2P`, `PV3P` (two labels added to the drawn buses).
- `.tran 0.3` became `.tran 20m` (the 15 ms shade ramp of V1/V2 still starts inside the window). The closed-loop
  run writes a lot of data: add a `.save` line with the nodes you need before running long.

## Knobs (all `.param`, bottom right of the sheet)

| param | meaning |
|---|---|
| `Tsw`, `Tdead`, `Vlogic` | PWM period (5 u = 200 kHz), dead time, logic level. `FSWP` for the DLL follows `1/Tsw` |
| `TEN` | controller enable time; before it the duties are `D0A1 D0B1 D0A2 D0B2` (open loop) |
| `VSTEP1`, `VSTEP2`, `TSTEP` | manual voltage-difference reference steps (VM1-VM2, VM2-VM3) at `TSTEP` |
| `KSCALE` | gain scale, 0.3 = the firmware boot default (`kscale` in `7_Pi/pod/params.yaml`) |
| `MSEL` | 0 = M compiled into the DLL (params.h), 1 = the 100 kHz S9i M, 2 = `ctrl_M2.txt` |
| `FILT`, `FC` | 0 = first-order IIR at FC Hz; 1..8 = moving average over that many control ticks |
| `SAMP` | 1 = firmware hall sampling (4 point samples per PWM period, averaged per tick), 0 = ideal average, 2 = old firmware |
| `NOISE`, `KBERR`, `VM1SRC`, `VSTRP` | sensor noise (1 = bench level), B-phase gain error, VM1 source (0 = INA) |

The `.meas` lines (settled window 18-20 ms) give the voltage differences, circulating and shuffled currents,
duties, string power and the supervisor's peak stress; a `.step param KSCALE list 0.3 1` is the usual next move.

## Checked

QUX netlists the sheet without connection notes (every DLL pin on its own net, the drivers on their PWM pairs).
A 1.5 ms run (TEN 0.3 ms, VREF2 step 1 V at 0.8 ms) solved in 31 s: DLL gains built from params.h, PWM averages
1.51 V (46 % per FET, 200 ns dead time), hall outputs 1.63 / 1.66 V, converter-1 circulating current nulled to
1 mA, VM2-VM3 moving toward the reference.
