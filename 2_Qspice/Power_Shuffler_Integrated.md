# Power_Shuffler_Integrated.qsch

The hand-drawn `Buck Boost Full Bridge - v3.qsch` power stage (parasitics as drawn) with the firmware control stack,
as a set of hierarchical QSPICE sheets. Electrically it is the flat `Buck Boost Full Bridge - v3 - control.qsch`
(verified element by element, see *Checked*); it only reads better and is edited in one place.

Generated by `Claude's outputs/build_power_shuffler_integrated.py` from the v3 sheet (which it never writes). Rerun it
after editing the generator; hand edits to the sheets and the generator do not mix, so keep an edited copy under
another name. `Claude's outputs/verify_power_shuffler.py` checks the result (below).

## Sheets

| sheet | block | inside |
|---|---|---|
| `Power_Shuffler_Integrated.qsch` | top | PV string X1-X3 with lead inductors L1-L6, bypass diodes D4-D6, cable / copper inductors L23-L28, shade ramps V1 / V2, load I1, the reference string X11-X13 with its load I2, the three blocks, and the PARAMETERS / SIMULATION / MEASUREMENTS columns |
| `Shuffler_1.qsch` | XS1 | converter 1 as drawn: C1 / C3 / C5, V13, V4 / V7 sense sources, X4 ERUC23, M1-M4 with drivers X6 / X7, gate R / C, parasitic L7-L14 / L29 / L30, plus the TMCS1126 hall models |
| `Shuffler_2.qsch` | XS2 | converter 2 as drawn (mirror image): C2 / C4 / C6, V5 / V6, X5, M5-M8 with X8 / X9, L15-L22 / L31 / L32, plus the hall models |
| `Controller.qsch` | XC | `shuffler_ctrl_dll2.dll`, enable / reference / ramp sources, the `.param` test inputs, the open-loop duty override and two PWM_Modulator blocks XP1 / XP2 |
| `PWM_Modulator.qsch` | XP1, XP2 | the four HRTIM-style comparators of one converter |
| `HalfBridge_Driver.qsch` | X6-X9 | the 1ED3140 driver sheet the v3 drawing already used |

Right-click a block in QSPICE and open its schematic to look inside; every sheet carries its own title and notes.
Renders of every sheet: `Claude's outputs/figures/<sheet>.svg` / `.png` (made by the verify script).

## Files that must sit next to the top sheet

`Shuffler_1.qsch`, `Shuffler_2.qsch`, `Controller.qsch`, `PWM_Modulator.qsch`, `HalfBridge_Driver.qsch`,
`shuffler_ctrl_dll2.dll` (the control stack, 6_RTOS/ctrl_core built from `ctrl_dll/` with the current `params.h`),
`ctrl_M2.txt` (the M used when `MSEL=2`). `MyLibrary.lib` (the `pvmi` module model) is found through QSPICE's
library path (OneDrive Documents/QSPICE), as for v3.

## Ports and nodes

| block | ports |
|---|---|
| Shuffler_1 / _2 | `T` `M` `B` = the converter rails (top / midpoint = inductor common node / bottom), `PWM_AH` `PWM_AL` `PWM_BH` `PWM_BL` in (3.3 V logic), `HS_A` `HS_B` out (hall sensors: 1.65 V + 100 mV/A on A into the midpoint, 1.65 V - 25 mV/A on B, reversed as mounted) |
| Controller | `PV1P` `PV2P` `PV3P` (INA239 string nodes), `HS_A1` `HS_B1` `HS_A2` `HS_B2` in; `PWM_AH1` .. `PWM_BL2` out |
| PWM_Modulator | `RAMPA` `RAMPB` `DA` `DB` in; `PWM_AH` `PWM_AL` `PWM_BH` `PWM_BL` out |

Top-sheet nets, kept exactly as the flat sheet has them: `Out` = PV1+ at the load (string side of L23); `PV2P` = the
converter-1 side of L24, i.e. the M rail of Shuffler 1 (V13 sits inside the block between it and C5); `PV3P` = the
string side of L25; `T1` / `B1` = the converter-1 rails behind L23 / L25; `T2` / `M2` / `B2` = the converter-2 rails
behind L26 / L27 / L28. `Vtest` / `Vtest2` are the shade ramps of module 2 in the two strings.

Anything inside a block is named with QSPICE's bullet (U+2022): `I(V4•XS1)`, `V(DA1•XC)`, `V(PWM_AH•XP1•XC)`.
A port net has no inner name: use the top-sheet name (`V(HS_A1)`, not `V(HS_A•XS1)`). A top-level `.param` or
`.func` is visible inside every block.

## Knobs (PARAMETERS column of the top sheet, one `.param` per line with its meaning beside it)

| param | meaning |
|---|---|
| `Tsw`, `Tdead`, `Vlogic` | PWM period (5 u = 200 kHz), dead time, logic level; `FSWP` for the DLL follows `1/Tsw` |
| `TEN`, `D0A1 D0B1 D0A2 D0B2` | controller enable time; before it the legs run at the open-loop duties |
| `VSTEP1`, `VSTEP2`, `TSTEP` | voltage-difference reference steps (VM1-VM2, VM2-VM3) at `TSTEP` |
| `KSCALE` | gain scale, 0.3 = the firmware boot default (`kscale` in `7_Pi/pod/params.yaml`) |
| `MSEL` | 0 = M compiled into the DLL (params.h), 1 = the 100 kHz S9i M, 2 = `ctrl_M2.txt` |
| `FILT`, `FC` | 0 = first-order IIR at FC Hz; 1..8 = moving average over that many control ticks |
| `SAMP` | 1 = firmware hall sampling (4 point samples per PWM period, averaged per tick), 0 = ideal average, 2 = old firmware |
| `NOISE`, `KBERR`, `VM1SRC`, `VSTRP` | sensor noise (1 = bench level), B-phase gain error, VM1 source (0 = INA), string-voltage option |

The SIMULATION column holds `.tran 20m`, the `.save` lines (every measured node; add what you want to plot) and the
four `.func`s the blocks use: `hall(cur,gain)`, `duty(en,cmd,dflt)`, `pwm_top(rmp,dty)`, `pwm_bot(rmp,dty)`.
The MEASUREMENTS column (settled window 18-20 ms): `vd1` / `vd2` module voltage differences, `ic1` / `ic2`
circulating and `ish1` / `ish2` shuffled inductor currents, `da1` .. `db2` duties, `pout` string power, `stressmax`,
`hsa1` .. `hsb2` hall outputs, `pwmah1` / `pwmah2` top-FET PWM averages. `.step param KSCALE list 0.3 1` is the usual
next move.

## Checked (21 Oct 2026, `python verify_power_shuffler.py`, about 8 min)

- QUX netlists the top sheet with the four blocks as nested `.subckt`s (`Power_Shuffler_Integrated.cir` is kept
  next to the sheet). The `.subckt` port order equals the generator's port lists.
- Flattened against the QUX netlist of the flat control sheet: 135 elements and 117 nodes match one to one, every
  value identical except the hall / duty / PWM expressions that now go through `.func`; the library sub-circuits
  (ERUC23-4R1K, HalfBridge_Driver, STD45N10F7) are the same text.
- 1.5 ms closed-loop run (TEN 0.3 ms, VREF2 step 1 V at 0.8 ms, window 1.3-1.5 ms) of both netlists: the DLL
  builds its gains from params.h in both; duties 0.4975 / 0.4971 / 0.4956 / 0.4994, string power 1574.4 W and
  stressmax 0.1011 agree to four digits; PWM averages 1.51 V and hall outputs 1.63 / 1.66 V as before. The
  hierarchical netlist solves in 34 s, the flat one in 81 s.
- The circulating / shuffled inductor currents, the module voltage differences and the hall outputs are not
  judged: they are set by milliohm winding resistances and nanosecond switching edges, and a mere reversal of the
  flat netlist's element order moves them by more than the hierarchy does (ic1 0.066 -> 0.116 A reordered vs
  0.067 A hierarchical; vd2 0.274 -> 0.292 V reordered vs 0.277 V hierarchical). In open loop (`--open-loop`)
  the PWM, gate-driver, rail-voltage, load and power measurements of the two netlists agree to five digits.
