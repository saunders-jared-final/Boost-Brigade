# firmware/ — SIL port of the power-shuffler control stack

Hand-written, bit-faithful C99 port of the three MATLAB Function blocks
(inner MIMO controller / supervisory feasibility governor / adaptive-step P&O
MPPT), built to run inside `SIL_power_shuffler_sim.slx` via C Caller blocks
and, unchanged, on the downstream PIL/HIL targets (ATmega328P, then
STM32G474). No algorithm was redesigned, retuned or "fixed" — reference
quirks are preserved deliberately (list below).

```
core/     pure portable C99 - no I/O, no allocation, float32 only
  shuffler_ctrl.c/.h        inner controller, 50 us tick (ctrl_init/ctrl_step)
  shuffler_supervisor.c/.h  governor, 1 ms tick (sup_init/sup_step)
  shuffler_mppt.c/.h        MPPT, 1 ms tick (mppt_init/mppt_step)
  stack.c/.h                full stack @ 50 us: 20:1 decimation, sup->MPPT
                            order, rv/Iref 1 ms unit delays, Vref summation
  params.h                  ALL constants - GENERATED by matlab/export_params.m
sil/      Simulink-facing layer
  sil_wrappers.c/.h         flat C Caller entry points, static single-instance
                            state + sil_reset()
  INSTRUCTIONS.md           exact model wiring steps (read before touching .slx)
test/
  replay.c                  golden-vector replay harness (+ --selftest)
  unit_tests.c              behavioural checks + float32-vs-double-reference
  avr_check.sh              compile-only check under avr-gcc -mmcu=atmega328p
matlab/
  export_params.m           regenerates core/params.h (double-precision Minv/Mp)
  export_golden.m           dumps golden CSVs from a MIL run (lists the
                            To Workspace blocks to add first)
```

## Quick start (host)

```
cd firmware
cmake -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Runs the unit suite and the replay `--selftest`. Warning-free under
`gcc`/`clang` `-Wall -Wextra -Wpedantic -Wconversion -Wdouble-promotion
-Wfloat-conversion -Werror` (disable promotion of warnings with
`-DSHUF_WERROR=OFF`).

## Golden-vector acceptance flow

1. MATLAB: add the To Workspace blocks listed in `matlab/export_golden.m`,
   then run `export_golden` **on the MIL variant** (MATLAB Function blocks
   active). Writes `test/golden/golden_inputs.csv` + `golden_expected.csv`.
2. Host: `./build/test/replay test/golden/golden_inputs.csv
   test/golden/golden_expected.csv`
   Gates: duties < 1e-3, rv/Iref/beta < 1e-2, MPPT state exact. Per-channel
   max-error report always printed; nonzero exit on failure.
3. Wire the C Callers per `sil/INSTRUCTIONS.md` and run
   `shuffler_string_validate` (the 7-test suite) as the final SIL gate.

## Design decisions & portability rules

- **float32 everywhere, no `double`** — AVR `double` is 32-bit, so any host
  double would make SIL and PIL diverge. Enforced at build time by
  `-Wdouble-promotion -Wfloat-conversion -Werror` on `core/` (the AVR
  compile-only check proves 16-bit-int/toolchain compilability, not float32
  purity — avr-gcc compiles `double` silently since its double *is* 32-bit).
  `stdint.h` types only (AVR `int` is 16-bit).
- **No runtime `inv()`** — `Minv` and `Mp` are computed offline in double by
  `export_params.m` and rounded to float32 in `params.h`.
- **`MAT_CONST` / `MAT_RD`** (`shuffler_ctrl.h`): declaration + element-read
  hooks so the matrices can later move to AVR flash
  (`-DMAT_CONST='static const PROGMEM float'`,
  `-DMAT_RD(m,r,c)='pgm_read_float(&(m)[r][c])'`) without touching algorithm
  code.
- **No malloc / VLA / recursion / printf in `core/`**; all state lives in
  caller-owned structs.
- **First-call seeding**: the MATLAB persistent-empty init seeds the
  supervisor filters (`imf`, `idf`) and the MPPT `b0` from the *first-call
  inputs*. The C keeps that exactly via a `seeded` flag — `*_init()` arms it,
  the first `*_step()` seeds. `en == 0` reset semantics are ported verbatim.

### Integrator precision (design rule 6)

`xi += Ts*e` adds ~1e-7-relative increments at 50 µs — near the float32
mantissa limit (stall deadband |e| ≲ 1e-4 for |xi| ~ 0.1). Measured over a
2 s synthetic closed-loop-plausible run against a double-precision reference
(`test_stack_vs_double_ref`): max duty error 8.7e-5, rv 1.3e-4, beta 2.0e-5,
Iref 2.7e-6, zero MPPT state mismatches — an order of magnitude inside the
golden gates, so **the accumulator stays float32** (SIL == PIL bit
behaviour). If real golden replay ever shows drift: build with
`-DSHUF_ACCUM_DOUBLE` (CMake option `SHUF_ACCUM_DOUBLE=ON`), which widens
only the `ctrl_accum_t` integrator chain on host/ARM (AVR stays float32 —
its double *is* 32-bit), and record the deviation here.

### Timing model in `stack.c` (standalone only — Simulink keeps its own)

Boundary ticks (0, 20, 40, ...) follow Simulink single-tasking sorted order:
latch rv/Iref unit-delay outputs → controller → supervisor → MPPT (fresh
beta) → store delay inputs. The supervisor samples the duties computed at the
**same** boundary tick — **verified against the .slx**: the duty path into
the Supervisor block is a direct connection with no rate-transition delay,
and the model's rv delays (1 ms, IC 0) / Iref delay (1 ms, IC 12) match this
file's replication. `-DSTACK_SUP_DUTY_SAME_TICK=0` exists only as an escape
hatch should the model wiring ever change to a delayed (1/z) duty path.
(Under `=0`, `test_stack_vs_double_ref` AND `test_stack_delays_and_decimation`
intentionally fail — the double reference and the tick-380/400 Iref
expectations encode the same-tick default; the two orderings measurably
differ in beta/rv, which is exactly why golden replay can discriminate them.)

### Reference quirks preserved on purpose (do not "fix")

- Controller anti-windup recomputes `xi = Minv*(u_act - Mp*e)` **every**
  step, saturated or not.
- MPPT `Pav` is the *previous* window's average power; while `en == 0` it is
  the instantaneous `Vstr*Istr`.
- A beta move > `BTOL` between MPPT windows holds `iref`, re-arms the boot
  perturb, and reports state 0.
- The MPPT perturb window realigns to the re-enable instant after `en == 0`.
- The supervisor accepts `VM` and never uses it.
- Supervisor stress/beta/rv outputs are hard 0 while `en == 0` (stress is not
  computed).

## Regenerating params.h

Run `matlab/export_params.m` after any retuning (constants live in the
MATLAB Function blocks; mirror them into the script), bump `PARAMS_VERSION`,
rebuild, re-run tests. `matlab/gen_params.py` is a byte-identical Python
mirror (numpy/LAPACK) that produced the checked-in file — usable when MATLAB
is not at hand; keep the two in sync. The first MATLAB regeneration may flip
a last-digit ulp on a few `Minv` entries (different `inv()` rounding) —
expected and harmless.

## AVR check

`test/avr_check.sh` compile-only-builds `core/` + `sil/` with
`avr-gcc -mmcu=atmega328p -Os -Wall -Wextra -Werror` (auto-registered as a
ctest when avr-gcc is on PATH). No linking/upload — PIL scaffolding is a
later task.

## Formatting

`.clang-format` at this level; `clang-format -i core/*.[ch] sil/*.[ch]
test/*.c` before committing.
